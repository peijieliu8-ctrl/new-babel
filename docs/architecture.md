# 原型实现与企业化边界

## 结论

当前是**单进程、局域网、双人协作的交互验证原型**。新事项工作流由服务端保存事项、证据、决策、任务交付与验收；画布及清单视图读取同一公开状态。个人 Agent 指令由服务端处理，预览保存在发起请求的连接会话中，不向其他成员广播；人工发布后才写入公开画布。公开画布 Agent 基于已发布状态进行规则计算，不具备自主执行能力。

## 模块关系

| 层次 | 本版实现 | 责任边界 |
| --- | --- | --- |
| 浏览器工作台 | 画布、待我处理、决策清单、时间线、卡片详情、个人预览 | 展示与输入；不能单独决定锁、版本、决策或建议是否生效 |
| Web 与实时服务 | Express 提供页面/API，Socket.IO 处理加入房间和实时事件 | 校验请求、约束两人房间、广播公开状态 |
| 画布状态 | 目标、事项、卡片与来源、决策记录、任务验收、关系、评论、活动记录，按房间存为本机 JSON | 服务端是共享状态的唯一写入方；重启后恢复 |
| 事项 Workflow | 决策引用证据版本、异议回应、任务交付与独立验收、完成门槛 | 确定性校验；身份仍只以昵称模拟，不能替代正式审批 |
| 个人 Agent 模拟器 | `agents.js` 中的确定性预览 | 仅响应发起会话，不接模型、MCP 或外部工具 |
| 画布 Agent 规则 | 在每次公开状态变更后重算进度、依据、卡点、下一步和建议 | 只提供解释与建议；指派、审核、完成需人操作 |
| 自动演示播放器 | 浏览器脚本创建专用事项画布，以两个模拟连接调用相同的协作接口 | 仅用于教学演示；所有“人工确认”均标注为脚本代演，不赋予 Agent 真实审批权 |

## 一次个人 Agent 操作的控制点

| 顺序 | 处理 | 控制点 |
| --- | --- | --- |
| 1 | 用户选中卡片并输入私有指令 | 指令送到服务端处理，但不会写入公开画布或活动记录 |
| 2 | 服务端生成模拟预览 | 预览绑定浏览器连接，记录来源卡片版本与原文快照 |
| 3 | 用户检查内容并点击发布 | 原卡版本已变化则拒绝旧预览；改写需取得编辑锁 |
| 4 | 服务端保存产物并广播 | 新卡/改写进入共享画布，记录操作者、来源与时间 |

## 事项工作流的控制点

| 顺序 | 处理 | 控制点 |
| --- | --- | --- |
| 1 | 记录事项目标、负责人、待处理人和证据来源 | 数据和责任仍由参与者输入；来源需要名称、位置和版本 |
| 2 | 负责人记录决策 | 必须引用证据、回应当前异议；系统保存引用时的内容版本 |
| 3 | 来源内容或关键事项变化 | 旧决策标记为需复核，不能继续作为事项完成依据；新决策形成后，旧交付和验收退回 |
| 4 | 任务负责人基于当前决策重新提交交付说明 | 提交后进入待复核，不等于已完成；记录决策关联 |
| 5 | 不同的复核人接受或退回 | 服务端核对交付关联当前决策，记录操作者与时间；本版昵称仍可冒用 |
| 6 | 事项负责人宣布完成 | 必须满足目标、有效决策及当前决策下的任务验收门槛；昵称不构成正式身份认证 |

## 生产化判断

| 主题 | 本版可验证 | 金融机构落地仍需建设 |
| --- | --- | --- |
| 身份权限 | 昵称区分会话；随机房间链接用于演示加入 | 统一身份、房间/卡片级授权、审核人真实身份校验 |
| 数据治理 | 本机持久化与输入长度限制 | 数据分级、脱敏、加密、留存及删除策略 |
| Agent 与 MCP | 模拟函数边界，能验证预览和人工发布 | 模型网关、MCP/工具白名单、最小权限、沙箱和工具结果隔离 |
| 人工确认 | 目标、建议、决策、审核、完成由人点击生效；昵称只作演示区分 | 按动作风险分级确认、审批链与职责分离 |
| 审计回滚 | 活动记录、对象版本、旧预览拒绝 | 不可篡改审计、前后差异、版本恢复及回滚操作 |
| 可用性 | 单进程与本机文件适合双人 Demo | 多实例一致性、并发控制、备份与故障恢复 |

**判断：** 当前画布 Agent 不需要引入自主执行模型。先验证团队是否真的需要“目标和责任推动”的协作方式；当非结构化讨论使规则判断不足时，再评估真实模型。若将来允许 Agent 调用 MCP、浏览器、文件或内网系统，应将每个工具动作限定到具体权限、保留人工确认与审计，并设计可中断和回滚的执行链。
