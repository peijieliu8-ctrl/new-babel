# New Babel（原无限画布）沟通原型方案

## 结论

第一版验证三个闭环：**两人共同组织讨论 → 个人 Agent 私下生成并由人发布 → 画布 Agent 公开展示卡点并由人确认关键动作**。Web 服务运行在一台局域网设备上，另一人通过房间链接加入。首页提供独立画布的自动播放演示，供单人快速理解全流程。Agent 使用确定性的模拟结果，重点验证协作与责任边界，不将模拟结果展示为真实模型判断。

## 六个维度

| 维度 | Demo 选择 | 需要验证的问题 |
| --- | --- | --- |
| 业务价值 | 把分散聊天变成可追溯的观点、证据、步骤和结论 | 两人是否比聊天文档更容易看清分歧与下一步 |
| 用户场景 | 想法辩论；实施方案细化 | 模板是否足以引导真实讨论，而不限制自由表达 |
| 产品能力 | 自由卡片、语义连线、评论转卡、目标卡、责任字段、个人及画布 Agent | 关键讨论是否能沉淀为结构、责任与行动 |
| 技术实现 | 局域网 Web 服务，服务端广播状态；单卡编辑锁、版本校验；规则驱动的模拟 Agent | 两台设备操作能否同步，旧预览能否被安全拒绝 |
| 实施路径 | 先完成可运行 Demo，再组织两人使用测试与问题回收 | 是否能完整走通两个模板的演示路径 |
| 风险 | 链接与昵称没有企业级权限；模拟建议可能被误认为判断；局域网数据留存需要管理 | Demo 标识、虚构数据和人工确认是否足够清楚 |

## 画布信息结构

| 对象 | 必要信息 | 规则 |
| --- | --- | --- |
| 目标卡 | 两个模板均在画布上可见；含目标、完成条件、确认人、完成状态 | 人确认后才作为进度依据；修改后须重新确认 |
| 卡片 | 类型、正文、位置、负责人、审核人、状态、版本 | 同卡单人编辑；重要字段变更记录活动 |
| 连线 | 起点、终点、关系类型 | 辩论支持“支持/反驳/关联”；方案支持“依赖/关联” |
| 评论 | 所属卡片、作者、正文、时间 | 可转为关联卡片，原评论保留来源 |
| 个人 Agent 预览 | 私有指令、来源卡片版本、拟新增或拟修改内容 | 发布前仅发起操作的浏览器会话可见；服务端不向房间广播；来源变更则拒绝发布 |
| 画布 Agent 面板 | 进度、依据、卡点、待确认建议 | 只读取已发布的画布状态；不直接指派或宣布完成 |
| 活动记录 | 操作人、对象、动作、时间 | 用于 Demo 中复盘，不等同不可篡改审计 |

## 界面与交互

| 区域 | 主要内容 | 用户可完成的动作 |
| --- | --- | --- |
| 顶部 | 画布名、模板、参与者、分享链接 | 复制链接、查看在线人员 |
| 中央 | 可平移和缩放的无限画布 | 放置及拖动卡片、选择卡片、建立语义连线 |
| 侧栏 | 目标、卡片详情、评论 | 编辑责任字段、评论、评论转卡、确认目标 |
| 个人 Agent 区 | 指令、模拟预览、差异 | 私下生成、检查、发布或重新生成 |
| 公开 Agent 区 | 进度依据、卡点、待确认建议 | 查看来源、确认建议或暂不处理 |
| 活动区 | 最近变更 | 复盘谁在何时做了什么 |
| 自动演示播放器 | 当前模拟角色、步骤、进度与脚本说明 | 暂停、继续、重播、手动接管 |

## 自动播放的产品边界

| 项目 | 设计 |
| --- | --- |
| 演示环境 | 每次播放新建独立画布；重播不会覆盖先前画布或真实协作房间 |
| 角色 | 同一个浏览器发起两个实时连接，明确标为“模拟主持人 A”和“模拟成员 B” |
| 数据与 Agent | 使用虚构制度问答试点案例；个人 Agent 和画布 Agent 都是规则模拟，不调用模型或工具 |
| 人工确认 | 目标、发布、建议、审核和完成由脚本代演人工点击，界面持续标识“脚本模拟” |
| 接管 | 停止播放并断开模拟成员连接；用户可继续编辑或邀请真实协作者 |
| 解释范围 | 可展示控制流程和同步行为；不能证明真实模型效果、业务数据真实性或企业权限合规性 |

## 建议的 5–7 分钟演示路径

1. A 选择“想法辩论”创建房间，复制链接。B 在另一台设备以昵称加入。
2. A 创建主张卡，B 增加反驳卡并连“反驳”关系；双方看到近实时同步。
3. B 在主张卡评论并转为关联卡；画布保留原评论和新卡的来源。
4. A 选中卡片，向个人 Agent 输入指令，查看标明“模拟”的私有预览；B 看不到指令和预览。A 发布后双方才看到结果。
5. A 生成改写预览，B 修改原卡；A 的旧预览被拒绝，重新生成后才可发布。
6. 画布 Agent 指出尚缺的依据、负责人或审核项；A 确认一条建议后，画布与活动记录同步更新。
7. 再建“方案细化”画布，完成目标确认、步骤依赖、责任分配、进度查看与人工完成确认。

## 验收标准

| 编号 | 可观察结果 |
| --- | --- |
| A1 | 两台设备同房间新增、移动、评论、连线及字段变更近实时同步，刷新后仍可见。 |
| A2 | 同卡编辑只能由一人持有；另一人可看到占用者；断线或超时后释放。 |
| A3 | 个人 Agent 指令和预览只返回发起操作的浏览器会话，服务端不广播；发布后产物才进入公共画布。 |
| A4 | 原卡版本变化后，旧改写预览不能覆盖新内容，并提示重新生成。 |
| A5 | 已发布卡片、评论转卡、状态或目标变化后，两端公开 Agent 面板自动更新进度、卡点和下一步；依据可对应已发布内容；建议未确认前不改变任务、指派或完成状态。 |
| A6 | 人工确认记录操作者与时间；两个模板各能走通一条完整路径。 |
| A7 | 首页可一键自动播放；暂停后步骤不继续推进，重播创建新画布，手动接管后模拟成员退出；页面明确区分脚本模拟与真实操作。 |

## 生产化前必须解决

| 缺口 | 原因与方向 |
| --- | --- |
| 统一身份与权限 | 昵称可冒用，房间链接可转发；应接机构身份、房间和卡片级授权。 |
| 数据治理 | 讨论可能含客户与经营信息；需数据分级、脱敏、留存及删除策略。 |
| Agent 执行控制 | 未来接 MCP/工具时，应采用工具白名单、最小权限、沙箱和操作前确认。 |
| 审计与回滚 | Demo 活动记录可用于演示；生产需不可篡改记录、版本回放和可回滚机制。 |
| 效果评估 | 当前没有真实使用数据；应通过两人任务完成率、卡点识别准确率、人工确认率和复盘访谈验证价值。 |

**待确认：**正式试点的业务场景、参与角色、数据等级、内网部署方式及验收指标阈值。以上不影响使用虚构数据完成当前 Demo。
