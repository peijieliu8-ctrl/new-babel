# New Babel · 事项推进工作台原型

**一个可在同一局域网内由两人共同使用的 Web Demo。** New Babel 把跨部门讨论收束成事项、证据、人工决策和任务验收。画布用于展开关系，“待我处理”“决策清单”“时间线”用于推进和复盘。个人 Agent 只生成模拟预览，公开画布 Agent 只提出规则建议；关键动作仍由参与者确认。页面使用用户提供的 New Babel Logo 原图，文件位于 `public/assets/new-babel-logo.png`。

仓库同时包含配套 HTML 演示文稿，位于 [`presentation/`](presentation/)。演示文稿保留图片、视频、演讲备注和独立运行脚本，不包含本地安装生成的 `node_modules`。

## 启动

需要 Node.js 22 或兼容版本。

1. 在本目录运行 `npm install`。
2. 运行 `npm start`。
3. 创建者访问 `http://localhost:3000`。可直接点击“自动播放演示”，也可选择“事项推进”或“想法辩论”、填写昵称后手动创建画布。
4. 复制页面中的画布链接，让同一局域网内的另一位参与者在浏览器打开并填写昵称。链接的主机名需换成运行服务设备的局域网 IP 地址；服务启动时会显示可用地址。

可设置 `PORT` 环境变量更换端口，例如 `PORT=3100 npm start`。房间内容保存在本机 `data/boards/`，服务重启后仍可访问；该目录不会纳入 Git。

## 运行配套演示文稿

1. 进入 `presentation/`。
2. 运行 `npm install`。
3. 按该目录的 [`README.md`](presentation/README.md) 启动和查看演示文稿。

## 协作方式

| 方式 | 结构 | 建议体验重点 |
| --- | --- | --- |
| 事项推进 | 事项主卡、证据与异议、决策记录、任务交付及复核 | 让一个问题从提出走到可追溯的人工决策与验收 |
| 想法辩论 | 目标、观点、依据、质疑和结论 | 对同一想法添加支持与反驳，保留形成结论的过程 |

已有“方案细化”画布的链接仍可打开；新建入口优先呈现更适合验证组织协作成本的“事项推进”。

## 自动播放演示

首页点击“自动播放演示”，系统会新建一张**独立的演示画布**，用虚构的“字段口径反复确认”事项展示：双方意见与依据、模拟 Agent 整理分歧、脚本代演人工决策、任务交付和独立复核。播放可暂停、继续或重播；重播会新建画布，不清空原画布。点击“手动接管”会停止脚本并退出模拟成员，可继续编辑或邀请真实协作者。

演示中的“决策”“确认”“审核”“发布”均是**脚本代演人的动作**，不代表 Agent 获得自动审批或发布权限。演示数据全部为虚构示例；过程摘要只反映当前原型的结构和状态，不证明真实业务提效。

## 关键操作

| 操作 | 预期行为 |
| --- | --- |
| 两人加入相同画布 | 卡片、连线、评论及责任字段实时同步 |
| 推进事项 | 记录问题、来源和异议；形成有依据的人工决策，再提交任务交付结果供另一人验收 |
| 切换工作视图 | 在画布、待我处理、决策清单和时间线之间查看同一份事项状态 |
| 编辑卡片 | 服务端单卡编辑锁，同一时间只允许一人编辑；断线或超时释放 |
| 请求个人 Agent | 仅发起操作的浏览器会话看到指令和明确标识为“模拟”的预览；点击发布后才共享结果 |
| 预览后他人修改源卡 | 旧预览发布失败，需重新生成，避免覆盖新内容 |
| 查看画布 Agent | 已发布内容或目标变化后，两端自动更新进度、依据、卡点及建议 |
| 确认建议或完成画布 | 由人主动确认后生效，并留下活动记录 |

## 演示与生产边界

这是交互验证原型。昵称与房间链接不具备企业身份认证和细粒度授权；活动记录也不是不可篡改审计，画布中的人工确认不是机构正式审批。**请只使用虚构数据，不录入真实客户、合同、经营或机构敏感信息。** 本版 Agent 不调用模型、MCP、内网系统或任何外部工具。生产化需要统一身份、权限、数据治理、工具白名单、沙箱、人工确认、审计与回滚。
